### What is built (ij8.96, in progress)

- `/agents.txt` on the API face and `/api/v1/agents.txt` on the gallery host:
  the one URL he hands an arriving agent. Open, no key, no DB, no secret, the
  address taken from the request, **never `http://` for a real host** (caught on
  the live pod: behind the TLS-terminating proxy the app saw plain http and
  would have told a stranger to send its key in clear).
- An **API-only face** on `$ARTIFACTS_API_HOST`: agent API, onboarding document,
  health check, nothing else. The gallery does not exist on that name whatever an
  ingress says. **`ARTIFACTS_API_HOST` is not yet set in the deployment**, so
  today any such name still 404s — correct until the door exists.
- The router **fails closed** on any unknown host already (it always did), so a
  public route pointed at a *new* name cannot expose the gallery.

### What is waiting on Jeremy — two questions on his board

1. **How a private page is protected out there** (`w7xo46vp6knwr53cveo67t4jg5`).
   Page bodies are protected today only by a permanent random token in the
   frame's URL (`store.content_url`, `gallery.py:3184`); no login, and the
   `sec-fetch-dest` check is a header anyone can set. Once page origins are
   public, a leaked frame URL is a permanent public read. Recommended (a), with

   blocked by Safari on his phone), but the gallery minting a **short-lived frame
   link per open**, and a shared page getting a deliberately long-lived link.
   That is also what gives `artifact.visibility` (private|link|public — in the
   schema since day one, honoured nowhere) its job.
2. **Chrome text size** (`ie3yztkyt5lke4tpet74kafqka`) — confirms the morning's
   rem/px diagnosis and says where else to hunt.

### What stands between here and a real external agent

- **The door** (ij8.15): a Cloudflare tunnel route (tunnel `k8s-tenfourty`,
  routes live in the CF dashboard, not git) + an in-cluster ingress. Jeremy's
  account, operator's lane, and a network change that needs his explicit yes on
  the mechanism. **Nothing in this house is internet-exposed today** — even
  `warpgate.tenfourty.site` has no public DNS and no tunnel route.
- **Rate limiting** (ij8.100): none. Keys are strong (`art_` + 43 chars, hashed);
  failure is free and silent. Cloudflare's limiter is the cheap half, the app the
  thorough half.
- **A key onto the new machine**: `artifacts-admin new-key` mints one; no written
  procedure for getting it there safely (ij8.1).
- **The waiter** is still not in the client package (ij8.68); the onboarding
  document points at the raw events call instead.
- **The forge registry** serves the artifacts images anonymously on the LAN
  (homelab-4q6t, ops', stalled). A precondition for exposing the *forge*, not
  this service — ops confirmed nothing opens it tonight.
