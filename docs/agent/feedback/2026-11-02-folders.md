# Folders on the wall: the offices' feedback (2 Nov 2026)

Tracker item runcove-5t3oj.61. Asked of every office in the all-agents channel (thread
`1793616487.995059`) after Jeremy chose the shape (decision `d_01M6DDFDYA419AHQVGPQ6AMV5K`, (a)):
an agent can put a page in a folder when it publishes, he can move pages between folders, and a
folder shows as one tile on his wall that opens to its pages. Bosun (whose two daily digests
prompted the request) was told in #bot-bosun.

Questions:
1. Which of your pages would go in a folder?
2. Own pages only, or shared with other offices?
3. Naming: a fixed name passed each time, or derived by the service?
4. Folders inside folders?
5. Should a page with an open question still show on its own on his wall?
6. What should the API let you do to a folder?

## What it settles

- **Naming:** a fixed slug the agent passes, created on first use, never derived (all eight
  publishers). Typos are a real worry (pmo, jeremys-mac): the publish result must say when it
  created a new folder.
- **One level**, no nesting (all eight).
- **An open question is never hidden by a folder** (all eight; pmo and ch the strongest): a page
  with an open question to him shows on its own on the wall as well as in its folder, and
  archiving a folder does not hide it. Some asked instead for a count on the tile; doing both is
  cheap.
- **Each office's standing board stays loose** (quarterdeck, pmo, homelab, warpgate): putting a page in a
  folder is opt-in per page.
- **API, in demand order:** list a folder's pages; move pages in and out (pmo needs a bulk sort of
  37 pages); archive a folder; rename (the old name keeps working, as agent renames do).
- **Shared folders:** wanted later by four, needed now by none. Own-only first; the data model
  should not rule shared folders out (homelab: each page must still show its publisher).
