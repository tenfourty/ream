Backups that look after themselves

Getting from "backups that work when I check them" to "backups that tell me when they stop", in four steps that each leave the house better off than they found it.

2 of 4 doneUpdated

Why this order

Each step is useful on its own, and the order is by what would hurt most if we stopped after it. Off-site storage first, because a fire is the failure we could not recover from. Then knowing when it breaks, because the second-worst outcome is a backup that quietly stopped. Encryption and self-testing last: both are real, neither is worth delaying the first two.

The steps

doneEverything is copied off-site every night

Documents, mail and the VM images leave the house each night. Nine clean nights so far.

Done when: a restore from the off-site copy alone comes back whole — tested, it did.

doneThe photo library is included

The big one, and the one most likely to be missed because it lives somewhere different from everything else.

Done when: the off-site copy's size matches the library's within a few per cent — it does.

nowA backup that stops tells you

A check that asks whether a backup NEWER THAN YESTERDAY exists, rather than whether the job ran. The job running is what every check asked last time, and eleven nights went missing behind it.

Done when: the check is made to fail on purpose, by hand, and the alert actually arrives. Not when it is written.

heldThe off-site copy is unreadable without our key

Encrypting at rest, so the provider holds something useless to them.

Blocked on: where the key lives — asked on its own page, not yet answered. Everything else here can proceed without it.

nextThe restore is tested without anyone remembering to

A monthly restore into a scratch space that complains if what comes back is not whole. A backup nobody has restored is a hope.

Done when: it has run unattended twice, and one of those runs was against a deliberately corrupted copy and caught it.

What is actually waiting on what

  • Encryption waits on the key decision, and on nothing else.
  • The self-testing restore waits on encryption, because it has to test the copy as it will really exist.
  • The alerting does not wait on anything. It is being built now alongside the rest.
